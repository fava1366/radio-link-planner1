# امکان‌سنجی فاوا – نسخه اندروید

این پروژه یک WebView اندرویدی با شناسهٔ برنامه `ir.fava.emkansanji` است. خروجی APK آزمایشی از طریق GitHub Actions ساخته می‌شود.

## قابلیت‌های فعلی این نسخه
- انتخاب نقاط A و B روی نقشه و نمایش مختصات و فاصله
- تغییر نقشه بین تصویر ماهواره‌ای و نقشه خیابانی
- تنظیمات اولیه دو رادیو و محاسبه مقدماتی فاصله، شعاع فرنل و انحنای زمین
- نمودار شماتیک/ارتفاع آنلاین در صورت دسترسی به سرویس ارتفاع
- ذخیره پروژه روی دستگاه، بازکردن پروژه، ورود/خروج فایل JSON
- رابط ورود ایمیل/گذرواژه، ثبت‌نام و بازیابی گذرواژه با Firebase پس از پیکربندی
- کد اولیه همگام‌سازی پروژه‌های واردشده با حساب کاربر در Cloud Firestore

**محدودیت مهم:** گزارش فعلی ابزار غربالگری مقدماتی است؛ هنوز تحلیل کامل انسداد مسیر بر مبنای پروفیل زمین، ساختمان/درخت، بودجه لینک واقعی، یا تضمین دسترس‌پذیری رادیویی ارائه نمی‌کند. داده ارتفاع آنلاین ممکن است در دسترس نباشد یا موانع مصنوعی را نشان ندهد. برای استفاده عملیاتی، نتایج باید مهندسی و میدانی اعتبارسنجی شوند.

## ساخت APK از GitHub با گوشی
1. ZIP را استخراج کنید و محتویات پوشه `EmkanSanjiFava-Android1-main` را در ریشهٔ مخزن GitHub خود بارگذاری کنید (خود پوشهٔ تودرتو را به‌اشتباه دوباره داخل مخزن نسازید).
2. در مخزن، به تب **Actions** بروید و workflow با نام **Build Android APK** را اجرا کنید؛ با push به شاخه `main` یا `master` نیز اجرا می‌شود.
3. پس از موفقیت، وارد اجرای workflow شوید و از بخش **Artifacts** فایل `EmkanSanjiFava-debug-apk` را دانلود کنید. ZIP آرتیفکت را استخراج و APK را نصب کنید.

## پیکربندی Firebase
شناسه Android package name برنامه:

`ir.fava.emkansanji`

### 1. ثبت Android app
در Firebase Console → Project settings → Your apps → Add app → Android، همین شناسه را وارد کنید. نام نمایشی اختیاری است (مثلاً `Radio Link Planner` یا `امکان‌سنجی فاوا`).

### 2. ساخت Firebase Web app برای رابط وب
در Project settings → Your apps یک Web app نیز اضافه کنید. مقدارهای SDK config را در فایل زیر وارد کنید:

`app/src/main/assets/firebase-config.js`

این مقادیر شامل `apiKey`, `authDomain`, `projectId`, `storageBucket`, `messagingSenderId`, `appId` هستند. کلید خصوصی Service Account یا فایل‌های محرمانهٔ Admin SDK را هرگز در این فایل قرار ندهید.

### 3. فعال‌سازی ورود
Firebase Console → Authentication → Get started → Sign-in method؛ روش Email/Password را فعال کنید. ورود با تلفن به تنظیمات اضافی، تأیید reCAPTCHA، کشورهای پشتیبانی‌شده و محدودیت پیامک وابسته است؛ کد اولیهٔ رابط به معنی تضمین کارکرد پیامک در همه کشورها نیست.

**نکته فنی:** این برنامه رابط را از `file:///android_asset/index.html` اجرا می‌کند. احراز هویت وب، به‌خصوص reCAPTCHA ورود تلفنی، ممکن است در این مبدأ محلی WebView به محدودیت دامنه/مرورگر برخورد کند. برای نسخهٔ تولیدی قابل اتکا، پیشنهاد می‌شود ورود Firebase به SDK بومی اندروید منتقل و با دستگاه واقعی آزمایش شود؛ فعلاً این پروژه نسخهٔ آمادهٔ توسعه و آزمون است.

### 4. راه‌اندازی Firestore
Firebase Console → Firestore Database → Create database. سپس قواعد نمونهٔ `firebase/firestore.rules.example` را بازبینی و به قواعد پایگاه داده اعمال کنید. این قواعد اجازه می‌دهند هر کاربر فقط به مسیر `users/{uid}/projects` خودش دسترسی داشته باشد. هیچ‌وقت برای راحتی، قواعد عمومی خواندن/نوشتن را در نسخهٔ منتشرشده فعال نکنید.

### 5. حساب Premium
در این نسخه نقش Premium و پرداخت درون‌برنامه‌ای هنوز پیاده‌سازی نشده‌اند؛ برای Premium امن باید نقش کاربر از سمت سرور/Cloud Functions یا سامانه پرداخت معتبر کنترل شود، نه فقط با یک فیلد قابل‌ویرایش در برنامه.
